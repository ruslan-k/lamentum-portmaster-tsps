### 10.3 P0-H2a — exact correctness defect candidates in the current lifetime ledger

**Code inspection:** `native/lc2_life_events.h` as introduced by `runtime/lamentum-adapter.patch`.

* `lc2_life_events_alias_group(share_group,name,kind,delta)` first resolves an object but increments/decrements a **single global** `s->alias_views`, not a per-object/per-generation counter. This does **not** establish how many references or attachments keep *that* specific storage alive. A global diagnostic counter can remain, but must not drive per-object reclamation decisions.
* `lc2_life_events_delete_key(key,views)` writes `completion=unobserved`, subtracts `e->bytes` from `s->retained_bytes` and clears the entry regardless of whether aliases, attachments, views or pending GPU work still reference storage. This may be a valid **logical-name retirement** event, but the variable name `retained_bytes` and any inferred physical refund are misleading. Keep `logical_live_named_bytes` and `possibly_gpu_retained_bytes` **separate**; the second may be unknown. Likewise do not hide inconsistent accounting with the current clamp-to-zero subtraction.
* `lc2_life_events_storage_key()` updates totals when the instrumentation call runs and `glBufferData` admission wrappers issue GL later. A `glTexImage2D`/`glBufferData` respec can fail (or be deferred by the driver), so **pre-GL ledger mutation is not success evidence**. Do not credit storage or reclaim old storage until an explicit outcome is known.
* Current storage keys include share group/name/kind/target/mip/face/layer, but no context epoch and separate storage generation. The same GLuint reused after context loss or respec must never inherit a previous resource's physical identity. Current 2,048 history slots do not fix this distinction.

**Proposed implementation:**

1. Introduce `lc2_resource_id={share_group_epoch,context_epoch,kind,GLuint,name_generation}`; `lc2_storage_id={resource_id,storage_generation,target,level,face,layer}`; and an `attachment_ref={FBO_id,slot,storage_id}`. Key aliases by **full storage_id**. Maintain independent counters for logical name, live storage, pending-orphan storage, references, and conservative “backing unknown” status.
2. Use a transactional operation object `{op_id,resource_id,old_storage_id,requested_bytes,gl_error_prestate,gl_outcome,commit_time_ns,submit_serial}`. Drain existing GL error state without swallowing it; execute GL; observe error state **without changing game-visible strict error handling**; only commit a definitive successful transition. On failure/ambiguous outcome retain old backing as possible. Never interpret a successful GL call as proven physical-CMA allocation or as proof that replaced backing was immediately freed.
3. Model `glBufferData` orphaning, `glTexImage2D` respec/mips, renderbuffer resizing, FBO attach/detach, `glDelete*`, EGL surface/context destruction and share-group recreation. A GL delete retires a handle; defer physical release claims until last reference **and** demonstrated GPU completion. `glFlush` only queues commands; a validated `glFenceSync/glClientWaitSync` path may qualify completion, with a correctness-preserving fallback if unsupported or too costly.
4. Normalize all event records with `run_uuid,boot_id,pid,starttime,elf_sha256,thread_id,context_epoch,share_group_epoch,op_id,present_serial,monotonic_ns`. When event ring/full history overflow occurs, immediately mark all dependent reconciliation `INCOMPLETE`; don't silently report a smaller live set.
5. Add executable native mocked-GL cases: allocate A, alias A, allocate B, delete A (B references remain); detach last view of A; reuse A's numeric GLuint; create same number in another share group; respec failure; GPU completion delayed; context loss; duplicate detach; 512 live objects; >2048 historical keys; event loss; max-u64 increments. Property: physical bytes are **never** inferred as refunded while there is an unproven outstanding owner/use.

**Acceptance:** host fixtures demonstrate the alias counter cannot leak across resource identities, delete/respec do not produce phantom refunds, and uncertainty is carried through the reducer. This should be implemented before basing M4-C memory optimizations on the existing `retained_bytes` peak.
