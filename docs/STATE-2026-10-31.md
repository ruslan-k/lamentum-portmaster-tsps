## Managed patches in this build

- `tools/resfix` — `ManagerMenuPrincipal.GetResolutions()` returns one 1280x720@60 entry
  (`Screen.resolutions` is empty on this player; without it the settings screen crashed and
  `Start()` applied a 1080p target).
- `tools/actionpatch` — the embedded Input System action asset gets `<Keyboard>/arrow*` bindings
  for `Navigate` (`port/actions-keyboard.json`).
- `asmpatch --only=inputsystem-android` — adds the Android gamepad layouts; they read the `AGC `
  state, which **does not exist in the 2019.4 player** (no such string in `libunity.so`), so this
  one changes nothing for this title and is kept only for completeness.

## Controls

The pad's buttons arrive as Android KeyEvents; its axes never do (see above). `port/port.env` maps
them to the keyboard bindings the game already has:

```
UA_KEYMAP="up:up,down:down,left:left,right:right,a:return,b:3,x:1,y:2,start:escape,select:i,l1:space,r1:e"
```

d-pad = move / menu navigation, A = confirm, R1 = action (E), L1 = dodge (Space), Select = inventory
(I), X/Y/B = shortcuts 1/2/3, Start = Esc.

## Known limits

- Native gamepad axes are not reachable on a 2019.4 player; a controller build would need a
  2020.3+ player (data retarget), not a config change.
- Memory headroom is thin: if heavy scenes OOM, the next lever is texture downscale or ASTC 10x10.
- The port needs the game's own files (not in this repository).
